# House of Briar frontend and backend audit — October 8, 2026

Reviewed main f3f4ea0, the live public storefront, pending audit branches, database and authentication code, checkout/inventory/webhooks, uploads/moderation, customer accounts, API error handling, SEO routes, accessibility, dependencies, automated suites and Railway health/logs.

## Corrected in this change

- Homepage newsletter previously cleared the email and displayed success without saving. A validated, consent-required, rate-limited endpoint now stores one normalized subscriber per address in the persistent SQLite database. No bulk email campaign is sent by this change.
- Homepage measurements previously reported a prepared request without submitting it. They now use authenticated item inquiries, persist in SQLite and enter the designer notification flow. Success appears only after the API confirms persistence. No open chat is enabled.
- The React custom-sizing form called an external Taskade flow despite the production House session backend. It now uses the same native inquiry endpoint. Caller-supplied contact details are replaced by the authenticated account identity.
- Measurement requests validate positive numeric inches, range and decimal precision on both client and server. API access requires a published, approved, unpaused listing and active designer. Requests are rate limited.
- Measurement controls have accessible names and show submission errors inside the product popup. Shared-browser storage risks are explained in both saved-profile interfaces. The homepage now retains the inseam field when saving a profile.
- The product popup no longer offers Add to Suitcase when shipping is unset.
- Private API responses default to no-store. Malformed JSON returns a safe 400 response; oversized JSON returns 413 rather than a generic 500.
- Added robots.txt and a dynamic sitemap with public pages, active designers and published pieces. Private routes are omitted. Added the missing server route for the React designer directory.
- Moved service-worker registration out of an inline script blocked by the existing content security policy.
- React sign-out now revokes customer and designer sessions on the server and only clears the local signed-in state after successful revocation.

## Verification

- Initial baseline: 171 backend tests and 20 frontend tests passed; production build passed.
- With regression coverage: 175 backend tests passed. Frontend tests and final production build run again before upload.
- Four additional API regressions cover real newsletter persistence/consent/deduplication/rate limits, authenticated measurement delivery and validation, disabled inquiry replies, safe JSON errors, private caching and sitemap exclusions.
- Backend npm audit: zero known vulnerabilities.
- Frontend npm audit: five high dependency entries trace to one braces advisory in the Tailwind build-tool chain. Installed/latest braces is 3.0.3; the advisory lists no patched version. A Tailwind major migration is not included in this corrective patch. These build tools process repository content, not customer-supplied patterns in the running backend. Reference: https://github.com/advisories/GHSA-vfj7-8cjw-p6xm .
- Local Playwright browser download failed in this environment. GitHub CI's required Chromium E2E job must pass before merge. Live public desktop inspection confirmed product popups, images, filters and shipping warnings; authenticated payment completion was not performed.
- Railway production was online with persistent volume, one running replica, no recent failed deployments and no staged work at inspection. Retrieved prior SIGTERM log lines corresponded to replaced deployments.

## Remaining operational items / limits

- Palm dress has no shipping amount on production. The designer must set a real price or explicitly choose free shipping. The audit does not invent a charge or mutate seller pricing.
- Production variable names were inspected through Railway (values withheld). EASYPOST_API_KEY and EASYPOST_WEBHOOK_SECRET are absent. Tracking verification and its carrier webhook require those credentials; tracking-gated payout release is therefore not operationally complete.
- Live tax configuration, real payment/refund execution and private admin/seller actions were not verified with financial transactions. Code fixtures test those boundaries but do not prove production account configuration.
- Existing PR #180 covers alternative icon changes and a React unknown-route fallback; #172 overlaps measurement validation. They are not merged wholesale: #172 checks before preventDefault, and #180 changes Apple touch icons to SVG. Both need reconciliation with this patch.
- Product social metadata is primarily updated in the React browser. Server-rendered per-product share metadata remains a separate SEO improvement.
- Newsletter persistence is enabled; mailing campaigns, subscriber export UI and an unsubscribe sending workflow are separate operational work before sending marketing campaigns.

This is an evidence-based engineering pass, not proof that every production path is defect-free.
